# Архитектура

Проект использует нативные ES-модули. Vite отвечает за локальный сервер и production-сборку, runtime-зависимостей нет.

```text
src/
  app/main.js                    Маршруты, композиция экранов, события
  components/                    Оболочка, обложки, статусы, диалог, уведомления
  data/books.js                  Начальный каталог и жанры
  features/
    catalog/catalog.js           Поиск, фильтры, список и просмотр книги
    reservations/reservations.js  Форма, активные брони и история
    admin/admin.js               Фонд, заявки и редактор книги
  services/library.js            Правила предметной области и хранение
  shared/                        HTML-экранирование, даты, иконки
  styles/                        Токены, компоненты, адаптивность, анимации
public/fonts/                    Локальные шрифты и лицензии
tests/library.test.js            Тесты правил и хранения
docs/                           Архитектура, дизайн и QA
.github/workflows/ci.yml         Форматирование, тесты и сборка
```

## Поток данных

Событие интерфейса → `library.commit(action)` → обновление последнего валидного состояния → копирование состояния → проверка правил и изменение копии → запись localStorage → публикация состояния → отрисовка и уведомление.

Ошибка записи не меняет состояние и не показывает ложное подтверждение. Повреждённое сохранение не ломает запуск: открывается исходный каталог с предупреждением. Ввод пользователя экранируется перед вставкой в HTML. Проверка схемы отсеивает неизвестные статусы, некорректные книги, дубли ID и ссылки на отсутствующие книги.

Доступность вычисляется из общего числа экземпляров и активных заявок. Подготовка и выдача сохраняют занятый экземпляр, отмена и возврат освобождают его. Нельзя уменьшить фонд ниже количества занятых экземпляров. Удаление записи с историей запрещено.

## Маршруты

| Маршрут                      | Экран                        |
| ---------------------------- | ---------------------------- |
| `#/catalog`                  | Каталог                      |
| `#/reservations?book=prince` | Бронирование выбранной книги |
| `#/reservations`             | Активные брони и история     |
| `#/admin`                    | Библиотекарь                 |

Hash-маршруты не требуют перенаправлений на статическом хостинге. По умолчанию Vite использует `base: './'`; переменная `VITE_BASE_PATH` задаёт префикс при деплое. GitHub Actions автоматически устанавливает `/<имя репозитория>/` для Pages, проверяет и собирает приложение, загружает только `dist/` и публикует его отдельным job после успешных проверок. Pull request не получает разрешений на публикацию.

## Граница учебного frontend

Событие `storage` обновляет другие вкладки; перед записью перечитывается актуальное сохранение. Это не заменяет транзакции сервера: одновременные записи из нескольких вкладок не имеют гарантии атомарности. Для реальной библиотеки нужны API, база данных, серверная проверка экземпляров, аутентификация, роли и защита персональных данных. Слой `services` позволяет заменить localStorage на API без переноса правил в шаблоны.

## Каталог и обновление сохранений

`catalog-model.js` отбирает и сортирует весь каталог до разбиения на порции. `catalog.js` хранит число видимых книг, добавляет по 10 карточек в существующую сетку и переносит фокус на первую новую книгу без автоматической прокрутки. Поиск, жанр, наличие, избранное и сортировка сбрасывают видимую порцию. Последняя неполная порция показывает точное количество; после конца списка кнопка исчезает.

`catalogRevision: 2` отмечает расширенный начальный каталог. Для сохранений без этой ревизии `migrateCatalog` добавляет только новые записи, проверяя ID и ISBN. Редактирование и удаление старых книг, собственные записи, брони и избранное сохраняются. Ревизия сохраняется при следующем изменении данных, поэтому удалённые после обновления книги не восстанавливаются.
