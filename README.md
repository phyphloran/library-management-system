# Переплёт · Library Management System

Учебная библиотека: **три связанных экрана на HTML, CSS и JavaScript**, адаптивная вёрстка, анимации и сохранение данных в браузере.

## Запуск

Нужен Node.js 22.12+ или 24 LTS.

```bash
npm ci
npm run dev
```

Откройте адрес Vite, обычно `http://127.0.0.1:5173`.

```bash
npm test              # Правила бронирования и хранения
npm run format:check  # Стиль исходного кода
npm run build         # Сборка в dist/
npm run preview       # Просмотр production-сборки
```

Не открывайте `index.html` двойным щелчком: ES-модулям нужен HTTP-сервер.

## GitHub Pages

Сайт: **https://phyphloran.github.io/library-management-system/**.

Публикация автоматическая: push в `main` запускает форматирование, тесты, сборку и деплой `dist/` через GitHub Actions. При ошибке проверки новая версия не публикуется. Pull request проходит проверки без публикации. Ручной запуск: Actions → Frontend checks and GitHub Pages → Run workflow.

Источник публикации в Settings → Pages → Build and deployment должен быть **GitHub Actions**. Настройка включена для этого репозитория. Workflow использует официальный Pages artifact и окружение `github-pages`; отдельная ветка `gh-pages`, PAT или дополнительные секреты не нужны.

В CI `VITE_BASE_PATH` задаётся как `/<имя репозитория>/`, поэтому JS, CSS, шрифты и favicon загружаются из правильной подпапки. При локальном запуске остаются относительные пути. Все экраны используют hash-маршруты, поэтому прямое открытие и обновление `.../library-management-system/#/admin` не требуют серверных redirects. Файл `.nojekyll` отключает обработку статических файлов Jekyll.

Для проверки такой же сборки локально в PowerShell:

```powershell
$env:VITE_BASE_PATH = '/library-management-system/'
npm run build
Remove-Item Env:VITE_BASE_PATH
npm run preview -- --base=/library-management-system/
```

Откройте `http://127.0.0.1:4173/library-management-system/`. При переходе с localhost на Pages сохранения не переносятся: у нового origin отдельный localStorage.

## Три экрана

### Каталог

`#/catalog` — поиск по названию, автору и ISBN, сортировка, фильтры жанра и наличия, избранное. Карточка открывает описание, год, страницы, ISBN и бронирование. Занятые книги забронировать нельзя.

### Бронирование читателя

Выберите книгу → «Забронировать книгу» → имя, почта, дата и согласие → «Подтвердить бронирование». Используйте тестовые данные.

`#/reservations` — активные заявки, номер брони, сроки и история. До выдачи бронь можно отменить. Заявка появляется в кабинете библиотекаря.

### Кабинет библиотекаря

`#/admin` — обработка заявок, поиск и фильтр статуса. Последовательность: «Подготовить» → «Выдать книгу» → «Принять возврат». Вкладка «Книжный фонд» позволяет добавлять, редактировать и удалять книги. Запись с историей бронирований защищена от удаления.

## Архитектура

```text
src/app/           Маршрутизация и события
src/features/      Каталог, бронирование, библиотекарь
src/components/    Общая оболочка и элементы интерфейса
src/services/      Предметные правила и хранение
src/shared/        Даты, экранирование HTML, иконки
src/data/          Начальный каталог
src/styles/        Токены, вёрстка, адаптивность, анимации
public/            Локальные шрифты, лицензии и favicon
tests/             Модульные тесты
docs/              Архитектура, визуальный ориентир и QA
```

Подробнее: [архитектура](docs/architecture.md), [проверки](docs/qa.md), [дизайн](DESIGN.md), [материалы](docs/design/assets.md).

## Адаптивность и доступность

Проверены ширины 320, 390, 768, 820, 1024 и 1440 px. На телефоне меню выдвижное, сетка двухколоночная, форма одноколоночная, таблица превращается в список. Есть видимый фокус, skip-link, подписи полей, статусы для скринридера, Escape и удержание фокуса в диалогах. `prefers-reduced-motion` уменьшает движение.

Анимации реализованы CSS: появление книг на полке, открытие диалогов, состояния кнопок и избранного, уведомления.

## Хранение и границы проекта

Данные сохраняются в `localStorage` под ключом `pereplet-library-v1`. Они переживают перезагрузку и обновляются между вкладками одного origin. В другом браузере или на другом порту будет отдельный каталог. Для сброса удалите этот ключ через DevTools → Application → Local Storage.

**Это frontend-демонстрация без сервера и авторизации.** Роли переключаются через меню, почта не отправляется, все заявки одного браузера видны в обоих кабинетах. Не используйте реальные персональные данные. Для внедрения нужны API, база данных и серверная проверка прав.

Остатки книг и сроки — учебные. Обложки — оригинальная векторная серия. Шрифты поставляются локально с открытыми лицензиями.

CI проверяет форматирование, модульные тесты и сборку при push и pull request.
